# Beyond the original request

What was added that the spec didn't ask for, and why.

| Addition                                                           | Why                                                                                                                                        | Where                                   |
| ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------- |
| **Guardrail against claimed-but-not-performed actions**            | The evals caught a model saying it had opened a carrier trace (no such tool). Replies may now only claim actions code executed             | ADR-023, `src/lib/guardrails/claims.ts` |
| **Email only to providers that don't train on inputs**             | Gemini's free tier trains on prompts; Gmail data falls under Google's Limited Use policy. Email uses Groq, plus keyword-only retrieval     | ADR-020                                 |
| **Atomic refund function in the database**                         | Code checks weren't enough under concurrency: the limit, frequency and idempotency checks and the insert happen in one transaction         | ADR-012                                 |
| **DMARC-aligned sender trust**                                     | Plain SPF/DKIM "pass" only proves the attacker's own domain. Trust requires the From domain to be authenticated                            | ADR-016                                 |
| **One account action per ticket**                                  | Limits the damage of any single confused or hijacked run                                                                                   | Orchestrator                            |
| **Demo isolation in RLS**                                          | The public demo viewer can only see fictional customers' tickets, never real emails sent to the inbox                                      | ADR-018                                 |
| **Per-client dashboard invites; demo viewer on demo tenants only** | Found while writing the runbook: the setup script would have exposed a real client to the public demo                                      | ADR-025                                 |
| **Fixed 15-case eval sample**                                      | Gemini Flash's free tier allows about one ticket a day; the sample keeps the comparison fair across models                                 | `evals/cases.ts`, ADR-022               |
| **Judge on a separate model, with anchored rubric**                | Grading had been spending the candidates' quota, and the first judge contradicted itself                                                   | ADR-023                                 |
| **Gmail polling from the database, with a lease**                  | Vercel Hobby crons run once a day; pg_cron runs every 2 minutes, keeps Supabase awake, and the lease stops overlapping polls               | ADR-024, migrations 11–12               |
| **Post-deploy smoke tests that wait for the new commit**           | Proves each production deploy over HTTP: headers, auth, CSRF, the bot check. Also runs daily as an uptime check                            | `.github/workflows/e2e.yml`             |
| **Dev-only values can't reach production**                         | The secrets push refuses Turnstile test keys and localhost URLs, after a manual push briefly sent the test keys                            | `scripts/secrets.mjs`                   |
| **Secrets via stdin only**                                         | Vault secrets never appear in a command line, a file or the terminal                                                                       | `push-supabase-vault`                   |
| **Plain-text email formatting, checked as sent**                   | Model Markdown showed as raw `**` in Gmail; the guardrail validates the exact text that's sent                                             | ADR-024, `src/lib/text/markdown.ts`     |
| **Daily demo reset (demo tenants only)**                           | A shared public demo wears out: one visitor's refund breaks the scenario for the next                                                      | ADR-019                                 |
| **Escalation notifications (instant + daily digest)**              | "Routed to a human" must reach a human: urgent escalations email the team, and the rest come in a morning digest                           | ADR-027                                 |
| **Two alert channels (email + ntfy push)**                         | A Gmail outage can't silence the alert about it; push needs no account                                                                     | ADR-026                                 |
| **Repeated-failure alerts, rate-limited**                          | The spec asked for email alerts; these are limited to one per hour per failure kind, with PII masked, so an outage doesn't flood the inbox | `src/lib/pipeline/alerts.ts`            |
| **Channel adapter guide (Zendesk, Slack, Intercom)**               | Concrete webhook, signature and identity mapping for each, not just "it plugs in"                                                          | `docs/CHANNEL_ADAPTERS.md`              |
| **Deployment runbook with rollback and checks**                    | So someone other than the builder can operate and recover it                                                                               | `docs/DEPLOYMENT.md`                    |
| **Beginner guides**                                                | How it works in plain English, plus a from-scratch setup guide                                                                             | `docs/guides/`                          |
